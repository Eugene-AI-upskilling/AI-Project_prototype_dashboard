1Executive Summary

핵심 요약

  • AX의 병목은 더 똑똑한 모델이 아니라 데이터 접근성
  • 흩어진 데이터를 정리하는 것이 모든 AX 과제의 선행과제
  • 리서치센터는 그 효과를 가장 먼저 증명할 PoC 무대
  • Research Data Copilot: 자연어 질문으로 데이터 위치 탐색, 읽기 전용 SQL 생성, 표·엑셀·차트 즉시 생성
  • SQL 지식이나 데이터 담당자 의존 없이, 질문 한 문장으로 탐색부터 시각화까지 완료
  • 리서치센터 PoC 검증 후, 전 부서 확장 가능한 구조

왜 데이터 정리가 먼저인가

데이터가 부족한 게 아니라, 꺼내 쓸 수 있는 형태가 아닌 상황 — 리서치를 포함한 전 부서 공통 이슈

흩어진 데이터+생성형 AI= 여전히 못 꺼냄 ✕
정리된 데이터+생성형 AI= 누구나 셀프 분석 ✓

12Data Ingestion

소스 특성에 맞춘 두 가지 적재 방식. 무리한 API 통합 대신 현재 사용 방식을 최대한 유지

자동 적재 API 가능 소스

API로 받아올 수 있는 소스는 스케줄 기반 자동 적재

1 API 연결 (KRX·내부 데이터 등)
2 정해진 주기로 자동 적재
3 카탈로그 자동 갱신

Bloomberg·Quantiwise·Refinitiv 등 실제 쓰는 데이터는, 다운로드한 엑셀/CSV를 업데이트 주기에 따라 매크로로 적재

1 기존 방식대로 엑셀/CSV 다운로드
2 업데이트 주기에 따라 매크로로 적재
3 로컬 서버 한 곳에 동일 포맷 동기화
4 갱신 확인 (HITL)

별도 API 재계약이나 무분별한 재배포 없이 현재 사용 중인 다운로드 방식을 그대로 활용하므로, 라이선스 리스크와 비용 증가 최소화

15ROI

Data Copilot AI 도입 ROI 전사 확장 효과

전사 확장 시 ROI는 단순 자동화 비용 절감을 넘어 데이터 계약·조회 시간·품질·통제 비용을 동시에 낮추는 구조

가장 먼저 확인 가능한 ROI: 데이터 비용 가시화

데이터 카탈로그가 구축되면 누가 어떤 데이터를 쓰는지, 같은 데이터가 중복 계약·중복 다운로드되는지 확인 가능. 즉, Data Copilot의 첫 비용절감 포인트는 데이터 효율화를 통한 중복계약 문제 해결

ROI 01 · 직접 비용 절감

데이터 중복계약·중복 구독 식별 및 정리

부서별로 따로 보유하던 벤더 데이터, 엑셀 다운로드, 내부 산출 데이터의 사용 현황을 카탈로그화. 동일 데이터의 중복 구매, 유사 데이터의 중복 유지, 사용 빈도가 낮은 데이터 계약을 식별해 계약 구조 조정 가능

절감 대상

중복 벤더 계약, 중복 데이터셋, 미사용 라이선스

측정 방식

데이터셋별 사용 부서·조회 빈도·계약 비용 매핑

기대 효과

가장 빠르게 재무 효과를 확인 가능한 영역

02
업무 시간 절감

데이터 위치 확인, 담당자 문의, 엑셀 정리, 차트 생성 시간을 줄여 리서치·영업·관리 조직의 반복 업무 단축

03
의사결정 속도 개선

보고서 작성 전 데이터 탐색 대기 시간을 줄이고, 필요한 수치를 즉시 확인해 회의·리포트·고객 대응 속도 향상

04
데이터 품질 비용 감소

용어 정의와 기준일을 통일해 부서·리포트 간 수치 불일치로 생기는 재작업과 검증 비용 감소

05
통제·감사 비용 감소

SQL 로그, 권한 분리, 읽기 전용 접근을 표준화해 사후 추적과 컴플라이언스 대응에 필요한 수작업 감소

16PoC Plan

WEEK 1 · 선행과제

문제 정의 · 카탈로그 초안

WEEK 2 · 선행과제

데이터 적재 · 샘플 DB

API 자동 적재와 벤더 엑셀 매크로 적재 체계 구성, 샘플 DB 구축.

WEEK 3–4

핵심 엔진 구현

Text-to-SQL·Semantic Layer·권한 체계 적용, 자연어 조회 데모.

WEEK 5

자동화 · 검증 화면

표·엑셀·차트 자동 생성 연결, SQL 로그·검증 화면 구현.

WEEK 6

사용자 테스트 · 발표

데이터 발견·추출 시간과 만족도 측정, 발표용 데모 정리.
